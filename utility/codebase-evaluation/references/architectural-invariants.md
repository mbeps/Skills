# Architectural & Code Invariants Reference

Authoritative diagnostic reference adapting core engineering invariants and quality disciplines (derived from large-scale refactorings across modern distributed, protocol-driven, and full-stack systems) into objective evaluation criteria.

Use this reference during codebase evaluations to verify that systems adhere to foundational architectural invariants.

---

## 1. Foundational Disciplines & Safety Invariants

1. **Preserve External Observable Behaviour**: Architectural decoupling and refactoring must never alter public API contracts, database schemas, or observable runtime behaviour without explicit, intentional migration gates.
2. **Clean Baseline First**: Evaluate whether codebases maintain passing test suites, clean static analysis checks, and green production builds before structural modifications.
3. **Characterisation Safety Nets**: Modules flagged as high-churn or high-complexity must maintain comprehensive characterisation tests before any refactoring or structural extractions are attempted.
4. **Enforce Shrink-Only Baselines**: Legacy systems must enforce tool baselines (e.g. linter/typechecker baseline files) so that technical debt only decreases and zero regressions enter CI.
5. **Trace Reachability Before Deleting**: AST call trees, test mocks, and reflection references must be fully traced before declaring any symbol, export, or migration script dead.

---

## 2. Data, Persistence & API Contract Invariants

6. **Schema & Migration Parity**: ORM schema changes must be validated against dry-run migration generations to guarantee zero unintended database drift.
7. **Distributed Cascade Integrity**: Polyglot storage architectures (e.g. relational database rows paired with cloud object storage files) must implement explicit application-level cascade cleanup hooks when foreign key rows are deleted.
8. **Identifier-Only Request Contracts**: Network boundaries must pass resource identifiers and delta payloads rather than trusting client-supplied full state objects, preventing context spoofing.
9. **Atomic Mutations Over Read-Modify-Write**: High-concurrency counters, balances, and quotas must execute atomic database expressions (`SET quota = quota - delta WHERE quota >= delta RETURNING quota`) rather than multi-step SELECT-modify-UPDATE sequences in application memory.
10. **Eliminate Magic Strings with Domain Enums**: Entity statuses, roles, and action identifiers must be centralised in domain enums or frozen string literal unions across application and test code.
11. **Four-Tier Model Segregation**: Systems must maintain strict model segregation:
    - *Raw Database Entities*: Mirroring table schemas.
    - *Core Domain Models*: Rich entities encapsulating domain invariants.
    - *Data Transfer Objects (DTOs)*: Serialised transport contracts.
    - *View / UI Options*: Presentational models and form state.
12. **Standardise Action Result Envelopes**: Server actions and API routes must return uniform envelopes (`{ success: boolean, data?: T, error?: string }`) paired with structured error logging.
13. **Persistence Layer Decoupling (DAO / Repository)**: Direct database and ORM driver queries must be abstracted behind dedicated repositories or domain services, isolating transport handlers from underlying persistence mechanisms.
14. **Chunked Concurrent Batching for Datastores**: Queries taking unbounded arrays in `IN` clauses must partition inputs into fixed batches matching datastore limits and resolve concurrently with `Promise.all` or worker pools.
15. **Nil-Tolerant Zero-or-One Queries**: Optional relations (favourites, drafts, profiles) must invoke nil-tolerant zero-or-one operators (`.maybeSingle()`, `findFirst()`) rather than exact-one assertions (`.single()`) to eliminate 406 / PGRST116 runtime crashes.
16. **Net Impact Quota Replacements**: File updates and asset replacements must compute net difference `(newSize - oldSize)` against user/tenant quotas rather than adding `(currentUsage + newSize)`, preventing false quota rejections for users near limits.
17. **Local Token Claims Verification in Gateway Middleware**: Edge middleware and API gateways must verify cryptographically signed token claims locally (`getClaims()`) instead of triggering blocking network-bound database lookups on every HTTP hop.
18. **Static Reverse-Index Precomputation**: Replace repeated multi-collection scans ($O(N \times M)$) on static or read-heavy datasets with precomputed reverse-index maps (`Map<Key, Entity>`) constructed at module initialisation.

## 3. UI, State & Component Invariants

19. **Server vs Client State Separation**: Client stores must be confined to ephemeral UI state (modals, active tabs, client-side drafts); authoritative data mutations must execute on the server and leverage framework cache revalidation.
20. **State Scope & Lifecycle Segregation**: Decouple static client singletons, authoritative identity sessions, and ephemeral UI atoms to eliminate global re-render cascades.
21. **Single Source of Truth Navigation**: Consolidate multi-surface navigation links, labels, and permission gates into declarative registry configurations with dedicated surface adapters.
22. **Unified Dual-Mode Entity Forms**: Consolidate near-identical Create and Edit entity forms into single parametric components to prevent clone drift.
23. **Headless Presentation-Logic Decoupling**: Extract mutation orchestration, URL query synchronisation, and side effects into headless hooks/composables, keeping UI components purely presentational.
24. **Design System Component Facades**: Route primitive UI consumption through internal design system wrappers (`components/ui/*`) to insulate feature components from third-party headless library churn.
25. **Vertical Hook Decomposition**: Decompose monolithic state hooks bundling $>5$ capabilities into single-responsibility, fine-grained reactive hooks colocated in domain folders.
26. **Deterministic Progressive Disclosure**: Replace fragile intersection observer loops with deterministic manual pagination ("Load More" controls) to eliminate runaway network churn, layout shift, and accessibility barriers.
27. **Harmonise with Design System Primitives**: Eliminate bespoke hand-rolled widgets (comboboxes, dropdown menus, modals) by consuming accessible, pre-built design system primitives with native theme tokens and ARIA compliance.
28. **Synchronise Long-Lived Listeners with Mutable Refs**: Guard audio drivers, media callbacks, WebSocket handlers, and interval loops against stale closures by bridging reactive state into mutable refs or store accessors.
29. **Compound Extension Slots Over Invasive Overlays**: Replace invasive absolute wrapper overlays (`position: absolute; inset: 0`) with designated child component slots (`rightAction`) and explicit event propagation boundaries.
30. **URL State Machine Modernisation**: Replace custom, bespoke URL query string synchronisation loops and manual history pushes with type-safe URL query state adapters (e.g. `nuqs`, TanStack SearchParams).
31. **Push Interactivity Boundaries to Leaves**: Push client component boundaries down to leaf interactive controls, converting static presentational wrappers back into server components to eliminate hydration overhead.

---

## 4. Domain Services, Modularity & Granularity Invariants

32. **Sub-Threshold Helper Decomposition**: When decomposing high-complexity functions, ensure extracted helpers do not remain complexity hotspots; push evaluation down to single items.
33. **Standardise Wheels & Wrap External Utilities**: Replace fragile hand-rolled logic (deep cloning, date manipulation, UUID generation) with vetted standard/community libraries wrapped in canonical domain facades.
34. **Fail-Fast Capability Guards**: Reject unsupported capabilities early with typed domain errors and status codes instead of silently degrading input.
35. **Topological Directory Harmonisation**: Colocate private subcomponents in `_components/`, enforce kebab-case naming, and group actions, schemas, and types by domain entity.
36. **Vertical-Slice File-Per-Function Endpoint Isolation**: Decompose monolithic controller and actions files into single-responsibility, file-per-function modules colocated in domain folders with 1:1 unit test files to maximise dead-code elimination.
37. **Framework-Free Pure Domain Logic**: Extract raw database transactions, vendor SDK calls, and business computations into pure, framework-agnostic functions in `lib/`, keeping reactive hooks as thin state orchestrators.
38. **Store-Free Domain Type Centralisation**: Declare domain entities and contracts in dedicated, framework-free `types/` modules so that non-UI services, pure functions, and server actions never import UI state management runtimes.
39. **Decoupled Client & Server Environment Validation**: Strictly decouple public client and server-only configuration schemas. Never evaluate server secrets eagerly during browser or SSR client bundle evaluation. Provide an eager, browser-safe client configuration singleton, and evaluate server secrets lazily on demand.
40. **The Granularity Goldilocks Zone**: Avoid both monolithic god files ($>500$ LOC) and micro-file explosion ($<10$ LOC). Reserve file-per-function decomposition for endpoints/actions with divergent dependencies, while colocating cohesive pure domain helpers operating on identical data shapes.

## 5. Tooling, Security & Boundary Invariants

41. **Acyclic Dependency Principle**: The module dependency graph must be a directed acyclic graph (DAG); zero bidirectional import cycles (`A ↔ B`) or peer domain cycles.
42. **Centralised Gateway Authorisation**: Security rules and role checks must be enforced authoritatively at gateway and middleware boundaries rather than scattered ad-hoc across controller conditionals.
43. **Zero Competing Tooling Engines**: The codebase must maintain a unified toolchain without overlapping, conflicting linters, formatters, or parsing engines.
44. **Sunset Ephemeral Migration Assets**: One-off backfills, temporary bridges, and data migration scripts must follow an explicit sunset protocol and be pruned from source control once deployed.
45. **Atomic Upserts Over Check-Then-Act**: Multi-step existence checks followed by conditional insert/update logic in application code must be replaced with single atomic database upsert expressions (`ON CONFLICT DO UPDATE`) or row locks to eliminate concurrency collisions.
46. **Guarded Handle Release in Shared Registries**: Global or shared resource registries (cancellation tokens, connection pools, socket maps) must verify handle instance equality before key deletion (`registry.get(id) === activeHandle`) to prevent premature eviction of newer concurrent operations.
47. **Per-Entity Async Serialisation**: Asynchronous queues, background jobs, and event-driven pipelines mutating a shared entity or aggregate root must declare per-entity concurrency locks or partition keys (`concurrency: { key, limit: 1 }`) to prevent state corruption.
48. **Complete Session Boundary State Cleansing**: Client-side reactive stores, browser storage, and in-memory caches must execute an authoritative purge hook on user sign-out/switch, and in-memory server caches must always incorporate user/tenant namespaces in cache keys.
49. **Clean Advertised Schema with Tolerant Preprocessing**: External-facing contracts and AI tool parameters must advertise clean, single-type schemas (avoiding `anyOf` / polymorphic unions), while using runtime preprocessing pipelines to tolerate stringified payloads or legacy wrapper structures.
50. **Trusted Spread Precedence**: When merging external or untrusted plugins/tools with system handlers, internal trusted primitives must always be spread last (`{ ...external, ...internal }`) or validated against collisions to prevent hijacking of core capabilities.
51. **Agentic Step Budget Synthesis Fallback**: Bounded multi-step execution loops must implement a terminal synthesis pass if step limits or token budgets are exhausted immediately following a tool call, guaranteeing that users receive a synthesized response rather than an empty message.
52. **Bounded Tool Delegations & Scratchpad Pagination**: Tool results and worker delegations returned to language model conversation contexts must be sanitized, condensed, and bounded (via dedicated model output adapters) while preserving full raw outputs in dedicated out-of-band scratchpads or object storage.
53. **Tool-Call Protocol Parity Invariant**: Every tool invocation in conversational state machines must be paired with an explicit tool-result (carrying an error envelope if execution threw, timed out, or aborted) to prevent protocol deserialization crashes on subsequent turns.
54. **Non-Destructive Collection Hydration**: Collection, sidebar, and layout loaders must perform non-destructive merges rather than wiping nested entity detail dictionaries in reactive stores.
55. **Pipeline Mutation Persistence Invariant**: Multi-step workflows and automated pipelines that execute side-effect mutations must verify artifact persistence before reporting step completion, failing fast with an explicit error if modified outputs are unpersisted.
56. **Configurable Callback Serve Origins**: Services and background jobs running in containerised network topologies must support configurable callback host origins (`SERVE_ORIGIN`) to prevent loopback blackhole packet drops across bridge networks.
57. **Hook Callback Reference Stability**: Callbacks, mutators, and error handlers exported from custom reactive hooks must maintain stable references via `useCallback` to prevent dependency array invalidation loops.
58. **Empty-String Environment Normalization & Test Fallbacks**: Environment validation layers must normalize empty string values (`""`) to `undefined` before executing schema validation, preventing false negatives in CI/CD environments where optional variables are declared empty. Modules executing eager environment parsing must support mock fallbacks or bypass flags (`SKIP_ENV_VALIDATION`) for build, lint, and test runs.
59. **Multi-Tier Payload Limit Parity**: Upload payload limits must be synchronized across all architectural tiers (reverse proxies, edge middleware, framework request limits, and backend handler configurations). Increasing limits at the server action or handler layer without updating edge middleware (`middlewareClientMaxBodySize` / Nginx `client_max_body_size`) produces silent early drop rejections.
60. **Direct Binary Streaming Over Base64 Serialization**: File uploads and multi-part data must be transmitted via native streaming constructs (`FormData`, multipart streams) rather than base64 Data URLs embedded in JSON payloads. Browser object URLs (`URL.createObjectURL`) created for client previews must maintain explicit lifecycle cleanup (`URL.revokeObjectURL`) to prevent memory leaks.
61. **Responsive Container Hit-Box Visibility Alignment**: Responsive layout containers with fixed or absolute positioning and high z-index must apply responsive visibility classes (`hidden md:flex`) to the positioning container itself rather than hiding only inner child markup, preventing invisible overlays that swallow click and touch events. Scrollable containers paired with fixed mobile navigation bars must maintain corresponding bottom viewport padding.
62. **Event Handler Callback Signature Isolation**: UI components passing parameterized action callbacks to native or framework event handlers (`onClick={fn}`) must explicitly wrap invocations in parameterless closures (`onClick={() => fn()}`) and enforce runtime type guards on optional parameters, preventing synthetic event objects from poisoning string arguments and routing paths.
63. **Dynamic Route Segment Rendering Declarations**: Framework pages executing mutations or reading real-time database state must explicitly declare dynamic segment revalidation (`export const dynamic = 'force-dynamic'`) to prevent static pre-rendering engines from caching and serving stale dashboard data.
64. **Relational Join Cardinality Normalization**: Code consuming joined database relations across ORMs or query builders must defensively normalize relationship cardinality (`Array.isArray(relation) ? relation[0] : relation`) to insulate against schema or join cardinality drift between 1:1 and 1:N relations.
65. **JIT Identity Sync (Lazy User Profile Provisioning)**: Distributed architectures with decoupled authentication providers and application database profiles must implement idempotent, Just-In-Time (JIT) provisioning helpers (`getOrCreateDbUser`) on authenticated data operations, preventing hard failures when webhook or trigger creation lags behind OAuth sessions.
66. **Folder-Scoped Storage Lifecycle Coupling**: Deletion of parent database entities must execute coordinated, folder-scoped cleanup of external object storage assets (`bucket.list(folder)` + `bucket.remove(files)`) rather than relying on brittle URL regex parsing, guaranteeing full reclamation of unreferenced media and thumbnail variants.
67. **Privilege Self-Demotion Guards**: Administrative role management interfaces must enforce client-side and server-side self-demotion guards, disabling or rejecting actions where the currently authenticated administrator attempts to revoke their own administrative privileges or lock their account.
68. **Canonical Site URL Resolution**: OAuth callback redirects, password reset links, and verification dispatches must resolve host origins through a centralized URL utility that normalizes protocol schemes, strips trailing slashes, and prioritizes canonical site URLs over ephemeral deployment hostnames.
69. **Bidirectional Route Protection (Inverse Auth Gates)**: Gateways and route middleware must enforce bidirectional route protection: protected application routes require authenticated sessions and redirect guests to login, while guest-only authentication routes (login, registration, reset) require unauthenticated status and redirect authenticated users to the root/dashboard, preventing session clobbering and redirect loops.
70. **Dynamic Trigger Column Guarding**: Database triggers and ORM entity lifecycle hooks operating across diverse schemas must verify column existence before assigning audit values or timestamps (`IF to_jsonb(NEW) ? 'updatedAt' THEN ...`), preventing mutation aborts on junction/join tables lacking audit columns.
71. **Responsive Media Aspect Preservation & Container Bounds**: User-submitted dynamic media components must prioritize `object-contain` paired with styled neutral background padding to prevent clipping of critical product context, and responsive framework image elements inside flex/grid layouts must declare explicit dimensional bounds or relative parent wrappers to prevent 0x0 rendering collapse.
72. **Reactive Collection Fallback Stability**: Custom hooks, selectors, and computed helpers returning array or object collections must maintain stable references for empty or fallback states (`EMPTY_ARRAY = []` or `useMemo`) to prevent breaking consumer `useEffect` dependency equality on every render pass.
73. **Asynchronous Auth Tri-State Resolution Invariant**: Route guards, permission checks, and conditional UI components must account for the composite asynchronous loading state (`authLoading || (!!user && !permissionsLoaded)`). Evaluating access denial or bouncing to login while resolution is in-flight introduces false unauthorized flashes and redirect loops.
74. **Closed-Enum Error Mapping Fallback Invariant**: Error presentation and notification pipelines translating error codes through lookup tables must implement a defensive fallback chain (`MAP[err.code] || err.message || DEFAULT_MESSAGE`), preventing empty message UI or runtime errors when encountering unexpected network or upstream errors.
75. **Denormalized Replica Consistency Invariant**: Architectures replicating canonical data across user subcollections, embedded snippets, or denormalized caches must update all replicas atomically via batched writes or transactional hooks, preventing persistent UI inconsistencies between summary and detail views.
76. **Stable Modal Declaration & Lifecycle Hoisting**: Modals, alert dialogs, and drawer components must be declared at stable page or layout roots rather than nested inside transient, collapsible, or overflowing parent containers (menus, popovers, dropdown lists), ensuring their lifecycle and focus traps remain intact when the trigger element closes.
77. **Dynamic Route Tri-State Resolution (Loading vs Not-Found vs Error)**: Dynamic route controllers and data fetchers must strictly distinguish pending state (`undefined`) from verified entity absence (`null`), immediately rendering 404 views rather than hanging indefinitely on loading spinners.
78. **Form Submission Disambiguation & Event Isolation**: Nested forms and action buttons inside interactive cards or lists must explicitly declare `type="button"` with isolated event handlers (`e.stopPropagation()`), preventing child button clicks from accidentally submitting parent forms or being swallowed by ancestor listeners.
79. **Destructive Mutation Ownership & Two-Step Confirmation Guard**: Destructive actions (deleting entities, revoking administrative privileges, removing members) must verify actor permissions on both frontend and backend and require an explicit two-step confirmation dialog before executing the state mutation.
80. **Route Transition State Isolation Invariant**: Shared reactive stores (Jotai, Redux, Zustand) and Context providers binding entity detail state must subscribe to route parameter changes and reset state on route transition or component unmount, preventing previous entity icons, titles, or cached data from leaking into the new view.
81. **Recursive Data Structure Depth Cap Invariant**: Hierarchical self-referential models (comments, category trees, reply chains) must declare explicit schema-level depth/level attributes and enforce a deterministic maximum depth cutoff (`depth <= MAX_DEPTH`) with UI flattening to prevent infinite nesting squishing and recursive rendering crashes.
82. **Creator Immutability & Last-Admin Tenancy Lockout Invariant**: Multi-admin access control systems must enforce creator/root owner immutability (prohibiting delegate admins from demoting or removing the entity owner) and sole-admin safeguards (preventing the last administrator from revoking their own administrative status or leaving an entity unadministrated).
83. **Distributed Datastore Cascading Deletion & Referential Integrity**: Deleting parent entities in polyglot or document datastores lacking native relational `ON DELETE CASCADE` must execute atomic batched deletions across dependent collections (bookmarks, saved posts, votes) and blob storage assets, and querying layers must defensively handle dangling references.
84. **Stacking Context Isolation & DOM Portal Invariant**: Floating overlay components (modals, dialog backdrops, popovers) must be portaled directly to the document root rather than mounted inside parent DOM subtrees that declare CSS transforms, filters, or overflow restrictions, preventing stacking context clamping and backdrop blur failures. All z-index assignments must strictly adhere to centralized design token scales.
85. **Unbounded Text Truncation & Responsive Sibling Protection Invariant**: Horizontal flexbox layouts containing arbitrary dynamic user text beside action buttons must declare `min-width: 0` with ellipsis truncation or stack vertically on mobile viewports, preventing long text from forcing sibling action buttons outside container boundaries.
86. **Deterministic Pagination Over Unvirtualized Infinite Scroll Invariant**: Data feeds lacking full DOM virtualization must employ deterministic manual pagination ("Load More" buttons or cursor pagination) rather than unbounded IntersectionObserver auto-appending, preventing mobile DOM bloat, memory exhaustion, and scroll jump thrashing.
87. **Toolchain Runtime Engine & Dependency Symmetry Invariant**: Build, lint, and test toolchains must declare strict engine version ranges in package manifests and pin all execution binaries in `devDependencies`, ensuring pristine CI/CD container environments reproduce local development verification without missing dependency errors.
88. **Mount-Time Listener Mutable Ref / Store Access**: Long-lived third-party hooks and SDKs (e.g. audio players, WebSockets, canvas engines) that register event callbacks once during initialization/mount must read reactive state and action handlers via mutable refs (`useRef`) or external reactive store subscriptions (`getState()`), preventing stale closure bugs where callbacks reference initial mount-time state.
89. **Dynamic Media UI Fallback Degradation**: Media components rendering user-uploaded or dynamic assets must defensively check for missing, null, or malformed URIs before rendering framework image optimizers, rendering deterministic fallback placeholder icons/visuals and preventing runtime crashes or empty layout collapse.
90. **Service-Layer Storage Orchestration Over Database Triggers**: Deletion and lifecycle operations across external cloud storage buckets must be orchestrated explicitly at the application/service layer rather than via database triggers. External network/storage failures must never abort primary database transactions, and database errors must not orphan storage artifacts without retry queues.
91. **Shared Metadata Creator & Ownership Attribution**: Shared or system entity schemas (e.g., artists, tags, categories) must record explicit creator/uploader ownership attribution (`user_id` / `uploader_id`), enabling granular Row Level Security (RLS), auditable provenance, and preventing unauthorized cross-user modifications.
92. **Touch Target Bounds & Propagation Isolation**: Touch-interactive surfaces on mobile devices must maintain minimum 48px touch bounding targets and clear spatial separation between primary controls and secondary navigation links. Event propagation (`e.stopPropagation()`, `e.preventDefault()`) must be isolated on nested interactive targets, or secondary clickable links must be conditionally hidden/disabled on touch viewports to eliminate fat-finger misclicks.
93. **Structural Slot Injection Over Overlaid Drag Handles**: Complex interactive list items requiring drag-and-drop or gesture handles must provide structural component slots (`rightAction`, `dragHandleSlot`) integrated directly into the DOM flow rather than absolute-positioned overlays that intercept touch/click events or collide with native scroll gestures.
94. **Symmetrical Validation Limits Across Architectural Tiers**: File upload constraints (maximum file size, allowed MIME types, aspect ratios) must be defined in a single source of truth and imported symmetrically across client-side validation schemas, user-facing UI copy/error messages, and server-side validation/action handlers, preventing client-server validation desynchronization.
95. **Test Runner Environment Pre-Configuration**: Test environments must inject required environment variables and configuration flags into test runner configuration (`vitest.config.ts`, `jest.config.js`) before module loading, preventing eager production configuration parsers from crashing the test suite during module import resolution.
96. **Dynamic Route-Level 404 Boundaries**: Dynamic route directories (e.g., `[id]/`) must implement route-level 404 boundaries (`not-found.tsx`) colocated with the dynamic segment, ensuring that when an entity is absent, framework `notFound()` calls render the appropriate contextual 404 view rather than falling back to unstyled root handlers or throwing uncaught errors.
97. **Redundant Route Boundary Hoisting (Inherited Framework Boundary Pruning)**: Nested route directories must rely on inherited ancestor loading and error boundaries (`loading.tsx`, `error.tsx`) rather than duplicating identical boilerplate boundary files across every subroute tier, preventing boundary sprawl, maintenance bloat, and divergent UI styling.
98. **Pre-Submit Input & File Schema Validation Gates**: Client-side interactive forms and upload inputs must execute schema validation (`safeParse`) on file change or prior to submit dispatch, immediately resetting invalid file inputs (`input.value = ""`) and displaying user-facing errors rather than persisting invalid state or dispatching doomed network requests.
99. **Proactive Storage Quota Metering & Soft Limit Feedback**: Multi-tenant and user-quota storage systems must proactively check and expose capacity utilization meters to users in management interfaces before upload operations, rejecting operations gracefully with informative capacity status rather than failing silently with unhandled backend quota errors.
100. **Refactoring Mock Path Synchronization**: Multi-module refactoring that renames or reorganizes source files must systematically audit and synchronize string literal mock paths in test suites (`vi.mock(...)`), preventing test suites from silently executing unmocked production implementations or crashing on missing modules.
101. **Root DOM Tree Hierarchy & Provider Invariant**: Root layout structures must strictly conform to HTML DOM specifications where `<html>` permits only `<head>` and `<body>` as direct children. Framework context providers, theme managers, and layout wrappers must reside *inside* `<body>`, preventing catastrophic SSR hydration mismatches.
102. **Collapsible Container Box-Model Padding Collapse**: Collapsible containers transitioning dimensions to zero (`w-0` or `h-0`) must simultaneously zero out padding and borders (`p-0 border-0`) or toggle `overflow-hidden` / `hidden`. Under `box-sizing: border-box`, residual padding remains visible and can occlude adjacent pointer events.
103. **Zero-State Primary Action Affordance (Empty-State Anti-Deadlock)**: Every empty state representation ("No items found") must provide an explicit primary action affordance ("Create Item", "Add Page") directly within the view to prevent user onboarding deadlocks.
104. **Transient Theme Surface Contrast Guarantee**: Loading skeletons, disabled elements, and placeholders must use contrast-guaranteed alpha-blended tokens (e.g. `bg-primary/5` or `bg-foreground/10`) rather than raw surface tokens (`bg-muted`) that match the parent container surface in certain theme modes.
105. **Layout Authentication Scope Containment**: Components and hooks executing authenticated queries or user-specific mutations must be encapsulated strictly within authenticated route group layouts (e.g. `(main)/layout.tsx`) that guarantee active session context, never inside public root layouts (`app/layout.tsx`) where unauthenticated visitors would trigger backend auth crashes.
106. **Asynchronous Route Segment Parameter Unwrapping**: In modern full-stack frameworks (e.g. Next.js 15+), dynamic route `params` and `searchParams` delivered as Promises must be unwrapped using `await` (Server Components) or `React.use()` (Client Components) before consumption, preventing runtime warnings and compilation errors.
107. **Toolchain Exclusion Negation Syntax Consistency**: Linter, formatter, and compiler file pattern configurations (e.g. Biome, ESLint, TypeScript) must strictly adhere to the engine's inclusion vs exclusion negation syntax (e.g. `!__tests__` rather than bare `__tests__` in inclusion lists) to prevent test or build artifacts from being accidentally linted or ignored.
108. **Compiler Flag & Deployment Runner Compatibility Matrix**: Production package manifests, compiler flags, and toolchain configurations must remain within the supported runtime matrix of the deployment hosting platform (Vercel, AWS Amplify, Docker), rejecting experimental or bleeding-edge compiler flags (e.g. `useTypeScriptCli`) until officially supported by deployment runners.
109. **Awaited Asynchronous Hierarchy Operations (No Floating Cascades)**: Recursive asynchronous mutations, hierarchical tree cascades (e.g. archiving or deleting document branches), and multi-collection transactions must explicitly await top-level recursive chains before returning from handlers. Omitting `await` releases execution prematurely, leaving descendants orphaned or terminating transactions before cascade completion.
110. **Client-Only Browser API Gating & Initial Render Determinism (`isMounted`)**: Client components accessing browser-specific globals (`window.location.origin`, `localStorage`, `document`) or mounting client-only portals/modals must gate execution behind an `isMounted` state initialized in `useEffect` or provide deterministic neutral fallbacks on initial render, ensuring the server HTML matches the initial client DOM and preventing React hydration mismatch crashes.
111. **CI/CD Pipeline Secret & Environment Parity**: Automated CI/CD workflow configurations (`.github/workflows/*.yml`) must inject required environment variables and service secrets symmetrically with application bootstrap validation schemas (`lib/env.ts`) and `.env.example`, preventing clean local builds from failing in CI test runners or container build steps.
112. **Blocker Dependency Pruning & Ecosystem Modernization**: When major framework and runtime upgrades are blocked by strict peer dependency constraints on an isolated, non-essential third-party package (e.g. legacy UI widget), architectures must prioritize auditing and pruning the blocker dependency over freezing dependencies or forcing unsafe `--legacy-peer-deps` overrides.
113. **Filter State Source Invariant (The Filter Collapse Paradox)**: Availability and visibility of filter controls, reset affordances, and category facets must evaluate the raw source collection (`source.some(predicate)`), never the active filtered array, preventing filter controls from vanishing once activated.
114. **Compound Component DOM Hierarchy & Direct Parent-Child Selectors**: Virtualized or filtered compound lists (e.g. cmdk, Radix) must maintain direct parent-child DOM relationships without intervening `<button>` or `<div>` wrapper nodes that break item-filtering calculations or leave large empty vertical gaps.
115. **Disabled Anchor Event Interception & Navigation Prevention (`asChild` Link Guard)**: Interactive elements rendering as anchor tags (`<a>` or Next.js `<Link>`) via polymorphic slot composition (`asChild`) must intercept click events (`onClick={(e) => { if (disabled) e.preventDefault(); }}`), set `aria-disabled="true"`, configure `tabIndex={-1}`, and apply CSS `pointer-events-none` when disabled, preventing browser navigation on disabled buttons.
116. **Hitbox & Event Delegation Alignment in Nested Controls**: Interactive controls must maintain congruent bounding hitboxes: outer clickable elements must encapsulate inner navigation links, or use unified slot composition (`<Button asChild><Link ...>`) to eliminate dead click zones on button padding and prevent links from overflowing container hitboxes.
117. **Multi-View / Tabbed Transient State Reset on Transition**: Multi-tab or multi-mode components sharing stateful controllers (carousel APIs, active slide indices, media counters) must reset transient navigation state upon tab switching, preventing out-of-bounds index errors or phantom background media playback.
118. **Static Prerender Parameter Generation Parity (`generateStaticParams`)**: Dynamic parameterized routes (`[id]`, `[slug]`) targeting static export or SSG hosting environments must export static parameter generation functions that enumerate all valid entities, preventing production deployment 404s.
119. **Canonical Root-Relative Static Asset Resolution**: Static assets, media paths, and navigation endpoints must be constructed with leading root slashes (`/projects/cover.png`) rather than relative slices (`projects/cover.png`) that resolve incorrectly on deep nested subroutes.
120. **Test Mock Hoisting TDZ & Factory Isolation (`vi.hoisted()`)**: Test mocks referencing external variables inside runner mock factories (`vi.mock()`, `jest.mock()`) must initialize variables via hoisting helpers (`vi.hoisted()`), preventing Temporal Dead Zone ReferenceErrors on runner initialization.
121. **Markdown & Syntax Normalization Code Span Shielding**: Text transformation routines and regex preprocessors operating on markdown must shield both multiline fenced code blocks (```` ```...``` ````) AND inline backtick code spans (`` `...` ``) before executing string replacements, preventing accidental corruption of code snippets.
122. **Static Data Map Relational Symmetry & Referential Integrity**: Bidirectional entity graphs maintained in static maps (e.g. projects linking to roles, skills referencing materials) must be protected by automated referential integrity test suites that assert reciprocal link symmetry and absence of dangling keys.
123. **Touch Screen Hover Media Query Guarding (`@media (hover: hover)`)**: CSS hover styling and transformations must be guarded behind `@media (hover: hover) and (pointer: fine)` to prevent interactive controls from remaining persistently stuck in hover states upon touch interaction.
124. **Dynamic Theme Token Synchronization for Vector & Canvas Graphics**: Embedded vector and canvas diagram renderers (Mermaid.js, Chart.js) must dynamically synchronize their color tokens with application theme changes, preventing illegible black text on dark backgrounds in dark mode.
125. **Mobile Sheet / Drawer Nested Scroll Conflict Resolution**: Mobile bottom sheets and touch-dismissible drawers must avoid nesting floating/portaled combobox popovers that conflict with drag-to-dismiss gesture tracking, using native select elements or accordion sections integrated into the natural scroll hierarchy.
126. **Orthogonal Filter Facet State Merge Invariant**: Multi-parameter filter state updates must execute functional delta merges (`setFilter(prev => ({ ...prev, facet }))`) rather than full object replacements, preserving independent orthogonal filter toggles (such as archive filters and pagination).
127. **Default-Deny or Synchronized Route Protection Matchers**: Route protection gateways and middleware must register all newly added private route segments in protection matchers or enforce default-deny routing rules, preventing unauthenticated access or sign-out failure on unregistered routes.
128. **Database & Auth Adapter Schema Contract Parity**: Database entity schemas and migration scripts must symmetrically supply all columns and models expected by active third-party authentication adapters (e.g. `idToken`, `password`, `Verification` table), and unserviced validation requirements (e.g. email verification without an SMTP provider) must be pruned to avoid onboarding deadlocks.
129. **Dynamic Cross-Origin Trusted Origins in Auth Gateways**: Authentication servers and API gateways must bind `trustedOrigins` configuration to dynamic, environment-driven origin lists (`env.TRUSTED_ORIGINS`), preventing cross-domain, staging, or mobile clients from receiving 403 Forbidden errors.
130. **Schema Nullability and Database Ingestion Invariant**: Validation schemas ingesting database records or resettable form payloads must explicitly declare optional fields as `.nullable().optional()` rather than bare `.optional()`, preventing runtime rejection when database drivers or JSON parsers supply `null`.
131. **Defensive Caught Exception Property Access**: Exception catch blocks must inspect error properties using runtime type narrowing and optional chaining (`error.issues?.[0]?.message ?? error.message`) rather than assuming fixed library-specific structures, preventing secondary `TypeError` crashes in error handlers.
132. **Strict Public Client Origin Resolution (No Unsafe Localhost Fallback)**: Client-side SDK and API clients must avoid hardcoded `http://localhost:3000` fallback defaults, relying on strictly validated environment variables or relative paths to inherit `window.location.origin` in production.
133. **Lazy Browser SDK Instantiation in Universal Modules**: Browser-only SDK clients (WebSockets, Pusher, WebRTC, IndexedDB) in isomorphic or shared modules must be instantiated lazily via getters or Proxies guarded by `typeof window !== "undefined"`, preventing Node.js deprecation warnings and SSR hydration crashes.
134. **Canonical Root-Relative API Endpoint Anchoring**: Client-side API requests must be strictly formatted with a leading root slash (`/api/...`) or constructed via centralized route registries, preventing relative URLs (`api/...`) from resolving against nested path segments and failing with 404s.
135. **Post-Submission Form Reset Validation Suppression**: Programmatic form field resets following successful action submission must omit `{ shouldValidate: true }`, preventing newly cleared fields from immediately triggering premature validation error messages.
136. **Automated Package Lifecycle Hooks for Code Generation Engines**: Projects dependent on schema-driven code generation or ORM compilers must declare automated package lifecycle hooks (`"postinstall": "... generate"`) in package manifests, ensuring fresh CI and deployment containers execute code generation automatically.
137. **Test Environment Process State Sandboxing & Ambient Context Mocking**: Unit and integration test suites modifying process-level environment variables must utilize test runner sandboxing utilities (`vi.stubEnv`) to prevent state leaks across test suites, and tests evaluating server actions must mock ambient server request contexts (`next/headers`).
138. **Multi-Action Dispatcher Contract & Return Parity**: When coarse dispatcher facades consolidate fine-grained operations, every action branch must enforce strict input schema validation matching action payloads and return strictly typed domain models, never degrading into unvalidated dictionaries or mismatched types.
139. **Dispatcher Parameter Forwarding & Signature Invariant**: Dispatcher and facade layers forwarding calls to underlying domain services must explicitly map and test every parameter, preventing parameter starvation (dropping optional inputs) and argument order inversion (`(target, source)` vs `(source, target)`).
140. **Strong API Return Contract Preservation**: Public APIs, RPC interfaces, and MCP tools must never replace typed return schemas (Pydantic models, TypeScript interfaces, Rust structs) with untyped dictionaries (`dict[str, Any]`, `list[dict]`, `Record<string, any>`).
141. **Non-Destructive Multi-Part Document & Archive Persistence**: When modifying a sub-element (e.g. worksheet, archive entry, subdocument) within a multi-part file, operations must preserve all sibling elements, sheets, charts, formulas, and metadata, rather than overwriting the entire file with an isolated fragment.
142. **Foreign Library Return Shape Defensive Normalization**: Invocations of external data science, spreadsheet, or computational libraries that return polymorphic shapes depending on dimension (scalars for single-cells, 1D arrays for single rows, 2D arrays for ranges) must normalize output into predictable structures before indexing.
143. **Non-Destructive Property Setter Invariant**: Assigning nullish, empty, or default values to domain entity properties or external library wrapper objects must be checked defensively before setter invocation, preventing underlying library setters from wiping styles, child objects, or throwing unexpected exceptions.
144. **Atomic Multi-Entity State Mutation & Feature Flag Commits**: Operations modifying multiple dependent fields, tables, or artifacts must ensure all mutations succeed and persist atomically. Partial mutations must roll back, and feature flags must be evaluated holistically.
145. **Cross-Entity & Formula Referential Integrity Preservation**: Renaming, moving, or modifying sheets, tables, or database keys must dynamically synchronize or validate referencing expressions (structured references, foreign keys, sheet-qualified range coordinates), preventing broken `#REF!` or orphan links.
146. **Locale-Invariant Canonical Data Ingestion & Parsing**: Parsing standardized canonical formats (ISO 8601 dates, UTC timestamps, standard numeric formats) must never employ locale-dependent heuristics (`dayfirst=True`, local decimal comma inference) that misinterpret unambiguous strings.
147. **Transitive Attribute Sandbox Enforcement**: Sandboxed execution environments (AST expression checkers, safe code runners) that restrict access to primitive I/O builtins (`open`, `os`, `sys`, `require`, `fs`) must recursively inspect and block transitive I/O methods and attributes on all imported foreign objects (`to_csv`, `read_pickle`, `save`, `load`).
148. **Protocol Diagnostic Error Preservation (No Opaque Masking)**: Error handling layers at API, RPC, or MCP protocol boundaries must retain original domain validation messages, field identifiers, and diagnostic context rather than stripping them into opaque generic error envelopes.
149. **Top-Level Module Dependency Completeness & Syntax Flexibility**: All standard library and third-party dependencies required across any execution branch must be imported at module load time or guarded with reachability tests; and expression parsers must accommodate standard syntactic and operator variations (`==` vs `=`, case-insensitive operators).
150. **Imperative Action Feedback Over Reactive Effect Cascades**: User-facing feedback (toasts, alerts, route navigation, and completion callbacks) resulting from mutations must be handled imperatively inside the user-initiated event or submission handler (`const res = await action(); if (res?.success) toast.success(...)`), rather than inside reactive effects (`useEffect`) watching persistent mutation result states. Placing feedback in reactive effects creates duplicate execution cascades and notification spam when dependent state changes or refetches trigger component re-renders with new callback instances.
151. **Protocol Revision Negotiation & Stateless Fallback**: Protocol and RPC server endpoints (e.g. Model Context Protocol / MCP) must provide backward-compatible stateless serving or negotiation (`legacy: "stateless"`) for established client revisions (such as `2024-11-05`), rather than strictly rejecting traffic with HTTP 400 Bad Request when modern envelope headers are absent, unless all client consumers are guaranteed to support the new revision.
152. **RFC 8414 Section 3 Discovery Path & URL Normalization Invariant**: OAuth 2.1 authorization servers and protected resource endpoints must support both RFC 8414 Section 3 path-inserted discovery (`/.well-known/oauth-authorization-server/<path>`) and root discovery (`/.well-known/oauth-authorization-server`, `/.well-known/openid-configuration`). Base URLs must be sanitized to eliminate trailing slashes (`replace(/\/+$/, "")`) to prevent double-slash corruption in discovery URLs (`//api/...`), and auth guards must symmetrically protect all supported HTTP verbs (`GET` and `POST`) against unauthenticated leakage or probing failure.
