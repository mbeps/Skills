# Vercel AI SDK Core API Reference

The Vercel AI SDK Core (`ai`) provides unified, vendor-agnostic functions for text generation, streaming, structured object synthesis, and vector embeddings.

---

## 1. `generateText`

Non-streaming completion function. Executes an LLM call and resolves once the generation and any tool calling steps are complete.

### Function Signature & Options

```typescript
import { generateText, isStepCount } from "ai";
import { openai } from "@ai-sdk/openai";

const result = await generateText({
  model: openai("gpt-4o"),
  
  // Prompt input (choose prompt OR messages)
  prompt: "Summarize the architectural differences between Next.js Pages and App Router.",
  // OR:
  // messages: [
  //   { role: "user", content: "Explain React Server Components." }
  // ],

  // System instructions (use instructions: string, NOT { role: "system" } in messages)
  instructions: "Always respond concisely in bullet points.",

  // Hyperparameters
  temperature: 0.7,      // 0.0 (deterministic) to 2.0 (creative)
  maxTokens: 1000,       // Max generation tokens
  topP: 0.9,             // Nucleus sampling
  presencePenalty: 0.0,
  frequencyPenalty: 0.0,
  stopSequences: ["\n\n---\n\n"],

  // Multi-step tool execution limit
  // Modern SDK supports stopWhen: isStepCount(maxSteps) or maxSteps
  stopWhen: isStepCount(5),

  // Observability & instrumentation
  telemetry: {
    isEnabled: true,
    recordInputs: true,
    recordOutputs: true,
  },

  // Lifecycle callback
  onStepFinish: async ({ text, toolCalls, toolResults, usage, finishReason }) => {
    // Invoked after each step in multi-step execution
  },
});
```

### Return Properties

| Property | Type | Description |
|---|---|---|
| `text` | `string` | The final combined generated text from the last step |
| `steps` | `StepResult[]` | Array of all execution steps (includes intermediate tool calls, tool results, tokens, and step text) |
| `usage` | `{ promptTokens, completionTokens, totalTokens }` | Aggregated token consumption across all steps |
| `finishReason` | `'stop' \| 'length' \| 'content-filter' \| 'tool-calls' \| 'error' \| 'other'` | Why the generation concluded |
| `response` | `{ id, timestamp, modelId }` | Metadata provided by the upstream LLM provider |

## 2. `streamText`

Streaming completion function. Returns an active stream of chunks as tokens are generated by the model.

### Function Signature & Streaming Utilities

```typescript
import { streamText, isStepCount } from "ai";
import { anthropic } from "@ai-sdk/anthropic";

const result = streamText({
  model: anthropic("claude-3-7-sonnet-20250219"),
  instructions: "You are a database performance tuning specialist.",
  messages: [
    { role: "user", content: "Write a high-performance PostgreSQL query for hierarchical comments." }
  ],
  tools: myTools,
  stopWhen: isStepCount(5),
  maxTokens: 4096,

  onChunk: ({ chunk }) => {
    // Triggered on every delta: text-delta, reasoning-delta, tool-call, etc.
  },
  onFinish: async ({ text, usage, finishReason, steps }) => {
    // Triggered once stream completes. Ideal for database persistence
  },
});
```

### Stream Consumers & Converters

```typescript
// 1. Next.js App Router AI Protocol Data Stream (for useChat / useCompletion)
return result.toDataStreamResponse({
  headers: { "X-Conversation-Id": conversationId ?? "" },
});

// 2. Raw UTF-8 text stream response (for standard fetch or EventSource)
return result.toTextStreamResponse();

// 3. Server-side async iteration of text tokens only
for await (const textPart of result.textStream) {
  process.stdout.write(textPart);
}

// 4. Access full stream events (text, reasoning, tool calls, tool results)
for await (const part of result.fullStream) {
  switch (part.type) {
    case "text-delta":
      console.log("Text chunk:", part.text);
      break;
    case "reasoning-delta":
      console.log("Reasoning chunk:", part.text);
      break;
    case "tool-call":
      console.log(`Tool invoked: ${part.toolName} (id: ${part.toolCallId})`, part.input);
      break;
    case "tool-result":
      console.log(`Tool result: ${part.toolName} (id: ${part.toolCallId})`, part.output);
      break;
    case "tool-error":
      console.error(`Tool error in ${part.toolName}:`, part.error);
      break;
    case "error":
      console.error("Stream error:", part.error);
      break;
  }
}
```

## 3. `generateObject` & `streamObject`

Structured output synthesis with compile-time TypeScript validation using Zod.

```typescript
import { generateObject, streamObject } from "ai";
import { openai } from "@ai-sdk/openai";
import { z } from "zod";

const taskSchema = z.object({
  title: z.string(),
  priority: z.enum(["low", "medium", "high"]),
  estimatedMinutes: z.number().int(),
  dependencies: z.array(z.string()),
});

// Atomic generation
const { object } = await generateObject({
  model: openai("gpt-4o"),
  schema: taskSchema,
  prompt: "Parse this task: Setup Postgres database with pgvector, takes about 45 mins, high priority.",
});

// Streaming structured output
const stream = streamObject({
  model: openai("gpt-4o"),
  schema: taskSchema,
  prompt: "Parse this task...",
});

for await (const partialObject of stream.partialObjectStream) {
  console.log("Progressive parse:", partialObject);
}
```

## 4. `embed` & `embedMany`

Generating vector embeddings for semantic search, retrieval-augmented generation (RAG), and Qdrant/pgvector storage.

### Basic Single & Batch Embedding

```typescript
import { embed, embedMany } from "ai";
import { openai } from "@ai-sdk/openai";

// Single embedding (e.g. for search query)
const { embedding, usage } = await embed({
  model: openai.embedding("text-embedding-3-small"),
  value: "Vector search over knowledge base documents",
});

// Batch embeddings (optimized bulk calls)
const { embeddings } = await embedMany({
  model: openai.embedding("text-embedding-3-small"),
  values: [
    "First document paragraph",
    "Second document paragraph",
    "Third document paragraph",
  ],
});
```

### Production Dynamic Provider & Prefix Routing

In multi-tenant or multi-provider systems, embedding models are resolved dynamically, may require task prefixes (e.g. `query: ` / `passage: `), and need batch chunking:

```typescript
import { embed, embedMany } from "ai";

const PREFIXED_MODELS = new Set(["nvidia/llama-nemotron-embed-vl-1b-v2:free"]);

// Query embedding with task prefix
export async function embedQuery(text: string, provider: ResolvedProvider): Promise<number[]> {
  const model = provider.sdkProvider.embeddingModel(provider.modelId);
  const value = PREFIXED_MODELS.has(provider.modelId) ? `query: ${text}` : text;
  const { embedding } = await embed({ model, value });
  return embedding;
}

// Bounded batch embedding (e.g. 50 chunks per request)
export async function embedDocumentChunks(
  chunks: string[],
  provider: ResolvedProvider,
  batchSize = 50,
): Promise<number[][]> {
  if (chunks.length === 0) return [];
  const model = provider.sdkProvider.embeddingModel(provider.modelId);
  const values = PREFIXED_MODELS.has(provider.modelId)
    ? chunks.map((c) => `passage: ${c}`)
    : chunks;

  const embeddings: number[][] = [];
  for (let i = 0; i < values.length; i += batchSize) {
    const batch = values.slice(i, i + batchSize);
    const result = await embedMany({ model, values: batch });
    embeddings.push(...result.embeddings);
  }
  return embeddings;
}
```
