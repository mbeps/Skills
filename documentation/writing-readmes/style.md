# Style

The README prose follows ASD-STE100, simplified technical English. The rules below cover sentences, point of view, spelling, and layout.

## Sentences

- Write short sentences. One idea per sentence.
- Use simple, factual words. Avoid long or complex words.
- Use the active voice. Write "The app stores transactions", not "Transactions are stored by the app".
- Do not use idioms, jokes, or exclamation marks.
- Do not use marketing language or superlatives: seamless, comprehensive, cutting-edge, robust, powerful, effortless.

Before and after:

- Before: "This application was designed with a focus on delivering a seamless and effortless user experience for managing all of your finances."
- After: "The application records income and expenses and shows monthly summaries."

## Point of View

- Write in the third person.
- Address the reader directly only in the setup steps, for example "Clone the repository".

## Spelling

Use British English spelling. Common pairs:

| British       | American      |
| ------------- | ------------- |
| Authorisation | Authorization |
| customisable  | customizable  |
| organisation  | organization  |
| colour        | color         |
| labelled      | labeled       |
| optimised     | optimized     |

Words ending in -ise and -yse, such as categorise and analyse, are British. Write -ise, not -ize.

## Layout

- Leave one blank line after each heading.
- Leave one blank line between markdown blocks: paragraphs, bullet lists, and code fences.
- Keep headings as headings. Do not bold them.
- Put every command in a code fence. Do not paste commands into prose.

## Consistency

- Use the same term for the same thing throughout the document.
- Do not add filler lead-in sentences such as "The system has several features designed to ensure a seamless experience". State the feature directly.
- Do not repeat content already covered by another section. The intro describes the project; the Features section lists the features.
