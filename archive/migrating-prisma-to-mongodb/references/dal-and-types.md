# Data Access Layer & Type Safety Reference

This guide covers building a type-safe Data Access Layer (DAL) using the native MongoDB Node.js driver as a drop-in replacement for Prisma.

---

## 1. Domain Types vs Document Types

When migrating away from Prisma, decouple application domain models (`id: string`) from MongoDB internal representations (`_id: ObjectId | string`).

```typescript
// types/db/user.ts
export interface User {
  id: string;
  name: string | null;
  email: string;
  emailVerified: boolean;
  image: string | null;
  createdAt: Date;
  updatedAt: Date;
  conversationIds: string[];
  seenMessageIds: string[];
}

// MongoDB document representation (internal to DAL)
export type UserDoc = Omit<User, "id"> & {
  _id: ObjectId | string;
};
```

## 2. Client Singleton & Connection Pooling

Next.js Turbopack / Webpack development hot-reloads re-evaluate modules frequently. Cache the `MongoClient` instance on `globalThis` to prevent connection exhaustion.

```typescript
// utils/db/client.ts
import { MongoClient, type Db, type Collection, ObjectId } from "mongodb";
import { env } from "@/config/env";
import type { UserDoc, ConversationDoc, MessageDoc } from "@/types/db";

declare global {
  var _mongoClient: MongoClient | undefined;
}

const client = globalThis._mongoClient || new MongoClient(env.DATABASE_URL);

if (process.env.NODE_ENV !== "production") {
  globalThis._mongoClient = client;
}

export const mongoClient = client;
export const db: Db = client.db();
```

> [!NOTE]
> Name the global variable `_mongoClient` to avoid identifier redeclaration conflicts with `export const mongoClient`.

## 3. ID Normalization & Query Utilities

Prisma masks MongoDB's `_id` into `id: string`. In a native MongoDB DAL, implement utilities to handle conversions bi-directionally.

### Document to Domain Entity (`fromDoc`)
Maps MongoDB's `_id` to standard domain `id: string`.

```typescript
export function fromDoc<T>(doc: any): T {
  if (!doc) return doc;
  const { _id, ...rest } = doc;
  return {
    ...rest,
    id: _id ? _id.toString() : rest.id,
  } as T;
}
```

### Safe ObjectId Conversion (`toObjectId`)
Converts 24-character hexadecimal strings to `ObjectId` while preserving non-ObjectId identifiers (such as string IDs generated by auth providers).

```typescript
export function toObjectId(id: string | ObjectId): ObjectId | string {
  if (id instanceof ObjectId) return id;
  if (typeof id === "string" && ObjectId.isValid(id) && new ObjectId(id).toString() === id) {
    return new ObjectId(id);
  }
  return id;
}
```

### Dual-Format ID Filter (`idFilter`)
MongoDB collections may contain mixed data during migrations (some documents with `ObjectId`, some with `string`). Use a dual filter:

```typescript
export function idFilter(id: string) {
  if (ObjectId.isValid(id) && new ObjectId(id).toString() === id) {
    return { $in: [new ObjectId(id), id] };
  }
  return id;
}
```

### Typed Collection Accessors
```typescript
export function getUsersCollection(targetDb: Db = db): Collection<UserDoc> {
  return targetDb.collection<UserDoc>("User");
}
```

## 4. Repository Pattern Implementation

Encapsulate all database operations in domain-specific repositories. This keeps server actions and API route handlers decoupled from database query syntax.

```typescript
// db/repositories/user-repository.ts
import type { User } from "@/types/db";
import { getUsersCollection, idFilter, fromDoc } from "@/utils/db/client";

export const userRepository = {
  async findById(id: string): Promise<User | null> {
    const collection = getUsersCollection();
    const doc = await collection.findOne({ _id: idFilter(id) as any });
    return doc ? fromDoc<User>(doc) : null;
  },

  async findManyByIds(ids: string[]): Promise<User[]> {
    if (!ids.length) return [];
    const collection = getUsersCollection();
    const docs = await collection
      .find({ _id: { $in: ids.map(idFilter) } as any })
      .toArray();
    return docs.map((doc) => fromDoc<User>(doc));
  },

  async update(id: string, data: Partial<Omit<User, "id" | "createdAt">>): Promise<User | null> {
    const collection = getUsersCollection();
    const result = await collection.findOneAndUpdate(
      { _id: idFilter(id) as any },
      { $set: { ...data, updatedAt: new Date() } },
      { returnDocument: "after" }
    );
    return result ? fromDoc<User>(result) : null;
  },

  async delete(id: string): Promise<boolean> {
    const collection = getUsersCollection();
    const res = await collection.deleteOne({ _id: idFilter(id) as any });
    return res.deletedCount > 0;
  }
};
```
